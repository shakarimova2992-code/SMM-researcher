# NicheScope

Мини-CRM для экспресс-аналитики Instagram по нише: поиск топ-аккаунтов по локации,
разбор топ-10 постов и Reels, подробный отчёт, топ-10 тем для контента и итоговая
презентация с чек-листом проблем и решений.

**Статус: рабочий прототип.** И поиск топ-аккаунтов по нише/городу (шаг 1), и анализ
конкретного аккаунта (топ-посты/Reels, отчёт — шаги 2-3) могут использовать **настоящие
данные Instagram** через Apify, если задан `APIFY_API_TOKEN` (см. «Реальные данные
Instagram» ниже); без токена, либо если запрос не удался, работает честный мок-режим
с явной пометкой в интерфейсе («✅ Реальные данные» / «🧪 Демонстрационные данные»).

## Возможности

1. **Поиск ниши** — по нише и городу возвращается рейтинг самых крупных аккаунтов.
2. **Анализ аккаунта** — топ-10 постов и топ-10 Reels с метриками (лайки, комментарии,
   сохранения, просмотры, ER).
3. **Подробный отчёт** — вовлечённость, рост аудитории, микс форматов, тепловая карта
   лучшего времени публикаций, паттерны хуков, топ хэштегов.
4. **10 тем для контента** — форматы, которые уже "залетают" в нише, адаптированные под
   выбранную тематику.
5. **Презентация** — слайд-отчёт с проблемами/решениями и топ-10 тем, экспорт в PDF
   через печать браузера (кнопка "Скачать / распечатать презентацию").
6. **Вход по email** (magic link, без пароля) — **одна ссылка/аккаунт пользователя даёт
   доступ к анализу ровно одного Instagram-аккаунта.** При попытке анализировать
   второй аккаунт пользователь увидит экран блокировки со ссылкой на уже привязанный
   аккаунт.

## Стек

Next.js 14 (App Router) + TypeScript + Tailwind CSS + Recharts. Хранилище пользователей/
токенов — файл `data/db.json` (простое JSON-хранилище для прототипа, не коммитится в git).

## Запуск локально

```bash
npm install
cp .env.example .env.local   # при желании укажите SESSION_SECRET
npm run dev
```

Откройте http://localhost:3000. На `/login` введите любой email — так как реальный
email-провайдер не подключён, ссылка для входа сразу покажется на экране (dev-режим).

## Как работает привязка "1 аккаунт на ссылку"

* При входе создаётся пользователь по email (`lib/db.ts`).
* Первый вызов анализа (`POST /api/analyze`) привязывает Instagram-username к этому
  email (`boundAccount`).
* Повторный анализ **другого** username для того же пользователя вернёт `403` с понятным
  сообщением — на фронтенде это красивый экран блокировки, а не голая ошибка.
* Сбросить привязку (например, по просьбе клиента сменить аккаунт) можно через служебный
  эндпоинт:

  ```bash
  curl -X POST https://ваш-домен/api/account/reset \
    -H "x-admin-key: <ADMIN_KEY из .env>" \
    -H "Content-Type: application/json" \
    -d '{"email":"client@example.com"}'
  ```

  Эндпоинт не вызывается из интерфейса — это ручной инструмент поддержки.

* Email-адреса из `UNLIMITED_EMAILS` (см. `.env.example`, по умолчанию —
  `shakarimova2992@gmail.com`) полностью освобождены от этого ограничения: для них
  `/api/analyze` никогда не привязывает и не блокирует username, можно анализировать
  сколько угодно аккаунтов подряд. В навигации дашборда для такого email вместо
  бейджа привязанного аккаунта показывается «🧪 Безлимитный тестовый доступ».
  Список настраивается в `lib/config.ts` или через переменную окружения
  `UNLIMITED_EMAILS` (через запятую) — используйте это только для своих
  тестовых адресов, не для обычных клиентов.

## Реальные данные Instagram (Apify)

И поиск по нише/городу (`/api/search`), и анализ конкретного аккаунта (`/api/analyze`)
умеют получать настоящие данные через [Apify](https://apify.com):

1. Задайте `APIFY_API_TOKEN` в `.env.local` (локально) или в переменных окружения
   Vercel (в проде). Токен берётся в apify.com → Settings → Integrations.
2. Если токен задан:
   * `/api/analyze` пробует `apify/instagram-profile-scraper` (профиль: подписчики,
     био, verified) и `apify/instagram-scraper` (сами посты и Reels: лайки,
     комментарии, просмотры, дата публикации, подпись, реальная ссылка на пост/Reel);
   * `/api/search` (поиск топ-аккаунтов по нише+городу) ищет посты по нишевым
     хэштегам (в т.ч. хэштег+город слитно) через `apify/instagram-scraper`
     (`searchType: "hashtag"`), собирает уникальных авторов найденных постов и
     получает их профили одним пакетным вызовом `apify/instagram-profile-scraper`,
     сортирует по числу подписчиков. **Важная честная оговорка**: у Instagram нет
     официального открытого поиска "по геолокации" — это приближение через хэштеги,
     а не гарантированно полный список всех аккаунтов города. Но каждый найденный
     аккаунт и его данные — настоящие, не выдуманные.
3. Если реальный запрос не удался (закрытый аккаунт, неверный username, слишком узкий
   запрос без найденных постов, исчерпан лимит Apify, сетевая ошибка) — сайт **тихо для
   пользователя откатывается на мок**, но честно показывает баннер
   «🧪 Демонстрационные данные» вместо того, чтобы выдать мок за настоящие данные.
4. Если токен не задан вовсе — работает только мок-режим, как в самой первой версии
   прототипа (`lib/mock/engine.ts`, детерминированная генерация).

**Что при этом остаётся честным ограничением даже с реальными данными** (Instagram
физически не отдаёт это ни через один открытый источник):

* **Сохранения (saves)** — не показываются на карточках постов/Reels вместо того, чтобы
  показывать выдуманное число.
* **История роста подписчиков** — график роста показывает заглушку "недостаточно
  данных", а не нарисованную кривую.
* **Бенчмарк вовлечённости по нише** — остаётся ориентировочной оценкой (детерминированной
  по нише), а не измеренным по реальной выборке аккаунтов показателем — это явно
  подписано как "~".

Всё остальное — подписчики, био, verified-статус, реальные лайки/комментарии/просмотры,
реальные подписи, реальные ссылки на посты, микс форматов и тепловая карта времени
публикаций — считается из настоящих данных, когда Apify их отдал.

**Поиск аккаунтов по нише/городу (шаг 1)** теперь тоже может использовать настоящие
данные (см. выше) — с оговоркой, что это приближение через хэштеги, а не точный
гарантированный охват всех аккаунтов города.

Код интеграции: `lib/live/apify.ts` (тонкий клиент к Apify REST API),
`lib/live/liveEngine.ts` (анализ конкретного аккаунта — профиль, посты, Reels, отчёт)
и `lib/live/liveSearch.ts` (поиск топ-аккаунтов по нише/городу) — маппинг сырых данных
Apify в типы `lib/mock/types.ts`, весь UI и отчёты работают одинаково независимо от
источника данных.

⚠️ Скрейпинг приватных сервисов формально не соответствует пользовательскому соглашению
Instagram (хотя в судебной практике США сбор именно публичных данных, в отличие от учётных
данных, отдельно рассматривался — см. дело Meta v. Bright Data, 2024); используйте на свой
риск и только для открытых аккаунтов, которые согласны на анализ.

## Как подключить реальную отправку email

Смотрите `lib/mail.ts` — там уже есть закомментированный пример на Resend. Задайте
`RESEND_API_KEY` в переменных окружения и раскомментируйте блок отправки.

## Хранилище пользователей

`data/db.json` — плоский JSON-файл, подходит для демо и малой нагрузки. Для продакшена
замените `lib/db.ts` на реальную БД (Postgres/Supabase/PlanetScale) — набор функций
(`getUser`, `upsertUser`, `bindAccount`, `createToken`, `consumeToken`) можно перенести
почти один в один.

⚠️ На большинстве serverless-платформ (Vercel и т.п.) файловая система эфемерна — при
каждом новом деплое/холодном старте `data/db.json` обнуляется. Для реальной эксплуатации
обязательно подключите внешнюю БД перед тем как давать ссылки клиентам.

## Публикация через GitHub

Репозиторий готов к пушу на GitHub:

```bash
git remote add origin <URL вашего репозитория на GitHub>
git branch -M main
git push -u origin main
```

Дальше — **деплой через Vercel** (самый простой способ "поднять" Next.js-проект из
GitHub, полностью бесплатно для старта):

1. Зайдите на vercel.com → New Project → Import Git Repository → выберите этот репозиторий.
2. В настройках проекта добавьте переменную окружения `SESSION_SECRET` (любая длинная
   случайная строка).
3. Нажмите Deploy — через минуту сайт будет доступен по ссылке `*.vercel.app`, и на неё
   можно будет подключить свой домен.

Обычный **GitHub Pages не подойдёт** — это чисто статический хостинг, а у сайта есть
серверная логика (вход по email, сессии, привязка аккаунта). Если нужен именно
GitHub Pages — потребуется убрать серверную часть и переделать на полностью статичную
версию без авторизации (сообщите, если такой вариант нужен).

```
app/
  page.tsx                        — лендинг
  login/page.tsx                  — вход по email
  dashboard/page.tsx               — поиск аккаунтов по нише
  dashboard/account/[username]/    — анализ, отчёт, идеи, презентация
  api/                              — auth, search, analyze, me
lib/
  mock/                            — генератор мок-данных (аккаунты, посты, отчёт, идеи)
  db.ts                            — файловое хранилище пользователей/токенов
  session.ts                       — JWT-сессия в httpOnly cookie
  mail.ts                          — отправка magic-link (dev-режим по умолчанию)
components/                       — переиспользуемые UI-компоненты
```
